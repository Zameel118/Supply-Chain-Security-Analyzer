Quaywatch — Phase 9 Deploy Guide (step by step)
================================================

Goal: put the API/worker/database on Render and the Next.js UI on Vercel,
with GitHub OAuth working end-to-end.

Do not reuse secrets from your local .env. Generate fresh production values.


------------------------------------------------------------
BEFORE YOU START — checklist of accounts
------------------------------------------------------------

You need:

  [ ] A GitHub account with this repo pushed (public or private)
  [ ] A Render account   — https://dashboard.render.com
  [ ] A Vercel account   — https://vercel.com
  [ ] Ability to create a GitHub OAuth App
      https://github.com/settings/developers

Estimated time: 45–90 minutes the first time (mostly waiting on builds).


------------------------------------------------------------
STEP 0 — Push the latest code
------------------------------------------------------------

1. Commit and push everything on your machine to GitHub
   (including render.yaml, frontend/, backend/, README).

2. Confirm render.yaml is at the REPO ROOT (same level as README.md).


------------------------------------------------------------
STEP 1 — Generate production secrets (on your machine)
------------------------------------------------------------

Open a terminal and run (stdlib only — no pip install needed):

  python -c "import secrets; print(secrets.token_urlsafe(48))"

  python -c "import base64, os; print(base64.urlsafe_b64encode(os.urandom(32)).decode())"

If you prefer using the project container instead:

  docker compose exec backend python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

Save the outputs somewhere temporary (password manager preferred):

  SECRET_KEY_PROD            = <first command output>
  TOKEN_ENCRYPTION_KEY_PROD  = <second command output>

Notes:
  - TOKEN_ENCRYPTION_KEY must be 32 random bytes, url-safe base64 (second command).
  - Never paste these into chat, screenshots, or commit them.
  - Never copy values from your local .env into Render.


------------------------------------------------------------
STEP 2 — Deploy backend stack on Render (Blueprint)
------------------------------------------------------------

1. Go to https://dashboard.render.com
2. Click New → Blueprint
3. Connect the GitHub repo that contains this project
4. Render should detect render.yaml
5. Name the Blueprint something like "quaywatch"
6. When prompted for environment variables marked sync: false, fill:

   TOKEN_ENCRYPTION_KEY
     → paste TOKEN_ENCRYPTION_KEY_PROD from Step 1

   GITHUB_CLIENT_ID
     → leave blank for now OR paste later (Step 4)
     → you can create the OAuth app after you know the API URL

   GITHUB_CLIENT_SECRET
     → leave blank for now OR paste later (Step 4)

   GITHUB_OAUTH_REDIRECT_URI
     → temporary placeholder is OK; you will set the real value in Step 3
     → example shape: https://quaywatch-api-xxxx.onrender.com/api/auth/github/callback

   FRONTEND_URL
     → temporary: https://placeholder.vercel.app
     → you will replace this with the real Vercel URL in Step 6

   CORS_ORIGINS
     → same temporary value as FRONTEND_URL for now

7. SECRET_KEY
   - If Render offers "Generate", use that
   - Otherwise paste SECRET_KEY_PROD from Step 1

8. Apply / Create Blueprint and wait until services are live.
   On the FREE plan you should only see THREE services:

     - quaywatch-db        (Postgres)
     - quaywatch-redis     (Key Value / Valkey)
     - quaywatch-api       (web — also runs the Celery worker in-process)

   Why not worker + beat?
     Render free plan does NOT support Background Workers. That is why
     sync failed with: "(service type is not available for this plan)".
     The API start script (scripts/start_web.sh) starts Celery inside
     the web service so scans still run without a paid Worker.

   Paid upgrade (optional later): see render.workers.yaml (Starter+).

9. Open the quaywatch-api service → copy its public URL, e.g.:

     https://quaywatch-api-XXXX.onrender.com

   Write it down as:  API_URL

10. After you pull/push the free-tier render.yaml fix to GitHub:
    Render Blueprint → Manual sync
    Then Manual Deploy quaywatch-api so the new start script runs.


------------------------------------------------------------
STEP 3 — Verify the API is up
------------------------------------------------------------

1. In a browser open:

     https://<API_URL>/health

   Expect JSON similar to:
     {"status":"ok","service":"quaywatch"}

2. Optional: open

     https://<API_URL>/docs

   You should see the FastAPI Swagger UI.

If health fails:
  - Check quaywatch-api Logs for missing SECRET_KEY / TOKEN_ENCRYPTION_KEY
  - Confirm DATABASE_URL and REDIS_URL were wired from the Blueprint
  - Wait for free-tier cold start (first request can take 30–60+ seconds)


------------------------------------------------------------
STEP 4 — Create the production GitHub OAuth App
------------------------------------------------------------

1. Go to https://github.com/settings/developers
2. New OAuth App

   Application name:
     Quaywatch (production)

   Homepage URL:
     Use your planned Vercel URL if you know it, e.g.
       https://quaywatch.vercel.app
     or temporarily use the Render API URL and update later.

   Authorization callback URL (MUST match exactly):
     https://<API_URL-host>/api/auth/github/callback

     Example:
     https://quaywatch-api-XXXX.onrender.com/api/auth/github/callback

3. Register the app
4. Copy Client ID
5. Generate a new Client Secret and copy it immediately

Write down:
  GITHUB_CLIENT_ID_PROD
  GITHUB_CLIENT_SECRET_PROD


------------------------------------------------------------
STEP 5 — Put OAuth + callback into Render
------------------------------------------------------------

In Render → quaywatch-api → Environment, set:

  GITHUB_CLIENT_ID
    = GITHUB_CLIENT_ID_PROD

  GITHUB_CLIENT_SECRET
    = GITHUB_CLIENT_SECRET_PROD

  GITHUB_OAUTH_REDIRECT_URI
    = https://<API_URL-host>/api/auth/github/callback

Save. Trigger a Manual Deploy of quaywatch-api (and ensure worker
inherits the same secrets via the Blueprint fromService links; if you
set secrets only on API, confirm worker still has TOKEN_ENCRYPTION_KEY
and SECRET_KEY from the Blueprint wiring).


------------------------------------------------------------
STEP 6 — Deploy the frontend on Vercel
------------------------------------------------------------

1. Go to https://vercel.com → Add New → Project
2. Import the same GitHub repo
3. Configure:

   Root Directory:   frontend
   Framework Preset: Next.js
   Build Command:    npm run build   (default is fine)
   Install Command:  npm install     (default is fine)

4. Environment Variables (Production):

   Name:  NEXT_PUBLIC_API_URL
   Value: https://<API_URL-host>
          (NO trailing slash)
          Example: https://quaywatch-api-XXXX.onrender.com

5. Deploy
6. When finished, copy the production URL, e.g.:

     https://quaywatch.vercel.app

   Write it down as:  FRONTEND_URL

7. (Optional) Add a custom domain later in Vercel → Domains.


------------------------------------------------------------
STEP 7 — Point Render back at the real frontend URL
------------------------------------------------------------

In Render → quaywatch-api → Environment, update:

  FRONTEND_URL = https://<your-vercel-host>
  CORS_ORIGINS = https://<your-vercel-host>

If you will also use a Vercel preview domain later, you can comma-separate:

  CORS_ORIGINS = https://quaywatch.vercel.app,https://quaywatch-git-main-xxx.vercel.app

Save and Manual Deploy quaywatch-api again.

Also update the GitHub OAuth App Homepage URL to the real FRONTEND_URL
(Settings → Developer settings → OAuth Apps → your app → Homepage URL).


------------------------------------------------------------
STEP 8 — End-to-end smoke test
------------------------------------------------------------

Do these in order:

  [ ] 1. Open FRONTEND_URL in a private/incognito window
  [ ] 2. Landing page loads (Quaywatch home)
  [ ] 3. Click "Sign in with GitHub"
  [ ] 4. Approve OAuth
  [ ] 5. You land on /dashboard and stay logged in after refresh
  [ ] 6. Submit a PUBLIC GitHub repo for scan
  [ ] 7. Worker progresses through checkpoint phases
  [ ] 8. Open the completed scan detail page
  [ ] 9. Toggle public share link; open /report/<token> logged out
  [ ] 10. Badge SVG URL returns an image

If login redirects but dashboard shows logged out:
  - FRONTEND_URL / CORS_ORIGINS mismatch
  - NEXT_PUBLIC_API_URL wrong or has a trailing slash
  - Cookie issue: API must be HTTPS and FRONTEND_URL must be HTTPS
    (production cookies use SameSite=None; Secure)

If scan stays queued forever:
  - Check quaywatch-api Logs for a Celery worker line (free tier runs
    worker inside the web service)
  - Confirm REDIS_URL / DATABASE_URL / TOKEN_ENCRYPTION_KEY on the API
  - Cold start: wake the service with /health, then retry the scan


------------------------------------------------------------
STEP 9 — Optional: periodic re-scans
------------------------------------------------------------

On the free plan there is no separate Beat service. Periodic re-scans
need either:

  A) A paid quaywatch-beat worker (see render.workers.yaml), OR
  B) Temporarily keep PERIODIC_RESCAN_ENABLED=false (recommended on free)

If you later add a paid Beat worker:

1. Render → quaywatch-api → Environment
     PERIODIC_RESCAN_ENABLED = true
2. Confirm quaywatch-beat is running
3. Redeploy as needed

Behavior:
  - Beat wakes hourly
  - Task only enqueues repos whose last COMPLETED scan is older than
    PERIODIC_RESCAN_MIN_AGE_HOURS (default 20)


------------------------------------------------------------
IF WORKERS FAILED TO SYNC (free plan)
------------------------------------------------------------

Symptom:
  Create background worker quaywatch-worker / quaywatch-beat
  → "(service type is not available for this plan)"
  Only api + db + redis show as synced (3 services)

Fix:
  1. Pull latest main (render.yaml no longer declares free workers)
  2. Blueprint → Manual sync  (should succeed with 3 services)
  3. quaywatch-api → Manual Deploy
  4. Confirm logs show both uvicorn and a Celery worker starting
  5. Continue the OAuth / Vercel steps — scans work without paid workers

Paid path later: merge render.workers.yaml services after upgrading.


------------------------------------------------------------
COMMON FAILURES (quick fixes)
------------------------------------------------------------

API crash on boot: "SECRET_KEY must be set" / placeholder rejected
  → Set real SECRET_KEY and TOKEN_ENCRYPTION_KEY (not change-me, not empty)

API crash: Fernet / decrypt errors after changing TOKEN_ENCRYPTION_KEY
  → Changing encryption key invalidates stored GitHub tokens.
    Users must log in again. Prefer setting this key once and keeping it.

OAuth "redirect_uri mismatch"
  → GitHub callback URL must exactly equal GITHUB_OAUTH_REDIRECT_URI

CORS / network errors in browser console
  → CORS_ORIGINS must include the exact Vercel origin (https, no path)

Free-tier cold starts
  → First request after idle can be slow; wait and retry /health

Worker not processing
  → On free: check quaywatch-api logs for Celery; Manual Deploy after
    the start_web.sh update. On paid: check the dedicated worker service.


------------------------------------------------------------
ORDER SUMMARY (cheat sheet)
------------------------------------------------------------

  1. Push repo
  2. Generate fresh secrets
  3. Render Blueprint → get API_URL
  4. Confirm /health
  5. Create GitHub OAuth App (callback = API_URL/.../callback)
  6. Set OAuth env vars on Render → redeploy API
  7. Vercel (root = frontend, NEXT_PUBLIC_API_URL = API_URL)
  8. Set FRONTEND_URL + CORS_ORIGINS on Render → redeploy API
  9. Smoke test login + scan
 10. Optional: enable periodic re-scans
